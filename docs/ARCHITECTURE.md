# АРХИТЕКТУРА ПРИЛОЖЕНИЯ

**Фаза 5 — проектное решение.** Приложение не реализовано: это спецификация структуры, интерфейсов и правил, по которым будет вестись сборка.

Статус проекта: **MVP / экспериментальное расчётное приложение.** Не production-ready.

## 0. Резюме для рецензента

Проектирование началось с измерения текущего состояния, а не с чистого листа. Найдено **шесть архитектурных дефектов**, три из которых делают заявленную архитектуру «JSON → движок» фиктивной. Главный из них доказан экспериментом, а не осмотром кода.

| № | Дефект | Тяжесть | Раздел |
|---|---|---|---|
| ARCH-1 | JSON не управляет расчётом: 5 констант продублированы в коде | **КРИТИЧЕСКАЯ** | 2.1 |
| ARCH-2 | 9 проверенных алгоритмов не помещаются ни в один из 12 запрошенных модулей | ВЫСОКАЯ | 2.2 |
| ARCH-3 | Слой Result Model отсутствует — его роль стихийно исполняет `engine/index.js` | ВЫСОКАЯ | 2.3 |
| ARCH-4 | Объект-бог `tables` передаётся во все модули (33 обращения в одном файле) | СРЕДНЯЯ | 2.4 |
| ARCH-5 | Гуа реализовано внутри `interactions.js` — чужой модуль | СРЕДНЯЯ | 2.5 |
| ARCH-6 | Инь-Ян реализовано внутри `meridians.js`, хотя запрошено отдельным модулем | НИЗКАЯ | 2.5 |

## 1. Целевая архитектура

```
        ┌─────────────────────────────────────────┐
        │  data/*.json + data/schema.json         │  СЛОЙ 1. Данные
        │  единственный источник чисел и таблиц   │
        └───────────────────┬─────────────────────┘
                            │ loader + validator (границы проверяются)
        ┌───────────────────▼─────────────────────┐
        │  Calculation Engine                     │  СЛОЙ 2. Расчёт
        │  чистые функции, без DOM, без времени   │
        └───────────────────┬─────────────────────┘
                            │ обычные объекты
        ┌───────────────────▼─────────────────────┐
        │  Result Model                           │  СЛОЙ 3. Модель результата
        │  форма, статусы, происхождение значений │
        └───────────────────┬─────────────────────┘
                            │ ChartSpec (данные без домена)
        ┌───────────────────▼─────────────────────┐
        │  Chart Engine                           │  СЛОЙ 4. Графика
        │  SVG-примитивы, ничего не знает о фэншуй│
        └───────────────────┬─────────────────────┘
                            │ DOM
        ┌───────────────────▼─────────────────────┐
        │  UI                                     │  СЛОЙ 5. Интерфейс
        └─────────────────────────────────────────┘
```

**Правило потока: строго вниз.** Слой N импортирует только N−1 и ниже. Обратных импортов нет; проверяется машинно (раздел 11).

**Почему ровно эти границы.** Каждая граница совпадает с точкой, где меняется природа данных: JSON → числа → доменный результат → геометрия → пиксели. Это позволяет тестировать слой 2 без браузера, слой 4 без фэншуй, а слой 5 — без пересчёта.

## 2. Найденные дефекты и их разбор

### 2.1 ARCH-1 (КРИТИЧЕСКАЯ). JSON не управляет расчётом

Фаза 4 перенесла календарные якоря и правила столпов в JSON. Но движок продолжает использовать собственные литералы:

| Величина | В JSON | В коде |
|---|---|---|
| Якорь столпа года 1984 | `calendar.epochs` | `ganzhi.js:59` — `mod(solarYear - 1984, 60)` |
| Якорь периодов 1864 | `calendar.epochs` | `flyingstars.js:32` — `const base = 1864` |
| Якорь годовой звезды 2024 | `calendar.epochs` | `flyingstars.js:46` — `wrap9(3 - (y - 2024))` |
| 3 дня = 1 год | `luck_pillars.conversion` | `pillars.js:122` — `deltaDays / 3` |
| Длина столпа 10 лет | `luck_pillars.pillarLength` | `pillars.js:136` — `(i - 1) * 10` |

**Проверено экспериментом, а не чтением кода.** В `luck_pillars.json` временно поставлено `daysPerYear: 6` и `pillarLength.years: 20`, затем выполнен расчёт и сверен с контрольным прогоном на нетронутых данных:

```
JSON изменён (3→6, 10→20):  startAge = 1.2815   шаг = 10
Контроль (JSON не тронут):   startAge = 1.2815   шаг = 10
```

Результат **побитово совпал**. Значит, декларация «JSON → движок» на этом участке не соответствует действительности: правки данных не влияют ни на что, а два источника истины рано или поздно разойдутся.

**Решение — правило CONST-1:** ни одна доменная константа не объявляется в коде. Модуль получает их из среза данных и падает при отсутствии:

```js
// НЕЛЬЗЯ                            // НУЖНО
mod(solarYear - 1984, 60)            mod(solarYear - anchors.yearPillar, 60)
```

Проверяется двумя способами: линтером запрещённых литералов (раздел 11) и «тестом на чувствительность» — изменение константы в JSON обязано менять результат (раздел 9.3).

### 2.2 ARCH-2 (ВЫСОКАЯ). Девять алгоритмов без модуля

В запрошенном списке из 12 модулей нет места для системы **Летящих звёзд (Сюань Кун 玄空)**:

```
C11 Три Ша, Тай Суй, Суй По      H4  Годовая летящая звезда   (VERIFIED)
H1  Полёт звёзд по Ло Шу         H5  Месячная летящая звезда  (VERIFIED)
H2  Геомантическая карта         H6  Дневная звезда  (PARTIALLY VERIFIED)
H3  Полярность звезды 5          H7  Период Сань Юань         (VERIFIED)
H16 Гора по азимуту              (8 VERIFIED + 1 PARTIALLY)
```

Соблазн — вложить их в `gua`, раз и то и другое «про направления». Проверка опровергает: наборы таблиц **не пересекаются вовсе** — Гуа читает только `gua`, звёзды читают `luoshu`, `mountains24`, `branches`, `interactions`. Это две независимые школы (Ба Чжай 八宅 и Сюань Кун 玄空) с разными входами (человек против здания) и разными циклами.

**Решение:** добавлен **13-й модуль `flying-stars`**. Список из 12 модулей принят как основа, но он не покрывал треть проверенных алгоритмов; молча растворить их в соседях означало бы создать модуль с двумя несвязанными обязанностями.

### 2.3 ARCH-3 (ВЫСОКАЯ). Слой Result Model отсутствует

В задании он есть, в коде его нет: `engine/index.js` (318 строк) одновременно вызывает счётные модули, собирает результат и раздаёт подписи (`labelPillars`). Следствия: UI читает сырой результат движка, поэтому изменение внутренней формы ломает интерфейс; статус значения (VERIFIED / INFERRED) в результате не переносится — число «85» выглядит одинаково независимо от того, проверено оно или предположено.

**Решение:** отдельный слой `src/model/`, где каждое значение обязано нести происхождение (раздел 6).

### 2.4 ARCH-4 (СРЕДНЯЯ). Объект-бог `tables`

Сейчас во все счётные функции передаётся весь пакет данных (`tables` встречается 33 раза в `index.js`, 12 в `interactions.js`). Любой модуль технически может прочитать что угодно, поэтому реальные зависимости не видны ни в сигнатуре, ни компилятору.

**Решение — «срезы возможностей» (capability slices):** модуль объявляет, что ему нужно, и получает только это (раздел 5.1).

### 2.5 ARCH-5 / ARCH-6. Код лежит в чужих модулях

`computeGua()` находится в `interactions.js`, `computeYinYang()` — в `meridians.js`. Оба переезжают в собственные модули `gua` и `yin-yang`.

## 4. Правила зависимостей

```
core     ← не зависит ни от чего
data     ← core
engine/* ← core, data (срез), другие engine согласно графу
model    ← core, engine
chart    ← core                       (домен НЕ импортируется)
ui       ← core, data, model, chart
```

Граф зависимостей внутри движка (обязан оставаться ациклическим):

```
calendar ──► stems-branches ──► bazi ──► luck-pillars
                    │            │  │
                    │            │  └──► interactions ──► flying-stars
                    │            │
                    ▼            ▼
                elements ──► meridians ──► indicators
                    │            ▲
                    └──► yin-yang┘
                 gua (независим)
```

Три запрета, каждый со своей причиной:

1. **`chart` не импортирует домен** — иначе график нельзя протестировать без фэншуй, а фэншуй нельзя перерисовать без графика.
2. **`engine` не импортирует `model`** — иначе счётные функции перестанут быть чистыми и переиспользуемыми.
3. **`ui` не считает** — единственная гарантия, что цифра на экране получена движком, а не подправлена в шаблоне.

## 5. Интерфейсы модулей

Общие соглашения: ES-модули; чистые функции; никаких `Date.now()` и `Math.random()` внутри расчёта (текущее время подаётся снаружи как параметр); на вход и выход — простые объекты; идентификаторы — латинские стабильные ID; русский текст только в слое `model/labels.js` и в `ui`.

### 5.1 Срезы возможностей вместо `tables`

```js
// src/data/slices.js
export const SLICES = {
  calendar:        ['calendar'],
  'stems-branches':['stemsBranches'],
  elements:        ['elements', 'stemsBranches', 'indicators'],
  'yin-yang':      ['stemsBranches'],
  bazi:            ['stemsBranches', 'calendar', 'bazi'],
  'luck-pillars':  ['calendar', 'luckPillars', 'stemsBranches'],
  interactions:    ['bazi', 'stemsBranches'],
  gua:             ['gua'],
  'flying-stars':  ['luoshu', 'mountains24', 'stemsBranches', 'bazi'],
  meridians:       ['meridians', 'elements'],
  indicators:      ['indicators', 'meridians']
};

/** Возвращает замороженный срез. Обращение к таблице вне среза — ошибка. */
export function sliceFor(moduleId, tables) { /* ... */ }
```

Срез **заморожен** (`Object.freeze`), поэтому расчёт не может незаметно изменить данные. Попытка прочитать таблицу вне среза даёт `DataError` с указанием модуля — то есть нарушение архитектуры обнаруживается при первом же запуске теста, а не при ревью.

### 5.2 Ключевые сигнатуры

```js

julianDayFromUTC(y, m, d, h?, min?, s?) -> number
utcFromJulianDay(jd)                    -> {year,month,day,hour,minute,second}

/* ── bazi ─────────────────────────────────────────────────── */

/* ── luck-pillars ─────────────────────────────────────────── */

/* ── elements ─────────────────────────────────────────────── */

yearAfflictions(yearBranchId)           -> {threeSha, taiSui, suiPo}  // C11

/* ── gua ──────────────────────────────────────────────────── */
computeGua(solarYear, gender)           -> {number, group, directions, validity}

/* ── flying-stars ─────────────────────────────────────────── */
flyStars(startNumber, forward)          -> Record<Direction, number>   // H1
periodForYear(solarYear)                -> number                      // H7
annualStar(solarYear)                   -> number                      // H4
computeGeomanticChart(params)           -> GeomanticChart              // H2
mountainForDegrees(deg)                 -> Mountain                    // H16

/* ── meridians ────────────────────────────────────────────── */
computeMeridians(elementTotals)         -> MeridianValue[10]           // F1
tripleBurnerGroups(meridianValues)      -> {upper, middle, lower} | null // F6

/* ── indicators ───────────────────────────────────────────── */
```

**Три функции обязаны возвращать пустой результат.** `qiPhaseOf().coefficient`, `tripleBurnerGroups()` при неизвестной агрегации и `healthIndex()` возвращают `null`, потому что формулы не опубликованы (K1, U-24, PH-F5). Это зафиксировано в интерфейсе, а не оставлено на усмотрение реализации: подставить туда правдоподобное число будет невозможно, не изменив контракт и не провалив тест.

## 6. Result Model — слой 3

Задача слоя: превратить сырые числа в результат, у которого **видно происхождение**. Иначе INFERRED-значение неотличимо от VERIFIED.

```js
/** Любая величина, показываемая пользователю. */
{
  value: 42.7 | null,
  status: 'VERIFIED' | 'PARTIALLY VERIFIED' | 'INFERRED' | 'NOT_VERIFIED',
  algorithmRef: 'F1',            // ссылка в calculation_spec.json
  placeholderRef: 'PH-F1'|null,  // если формула референса неизвестна
  conflictRef: 'K1'|null,        // если источники расходятся
  note: string|null
}
```

Правило: `value: null` + `status: 'NOT_VERIFIED'` — **нормальный, ожидаемый результат**, а не сбой. UI обязан отрисовать его как «не рассчитывается» с пояснением.

Форма профиля:

```js
Profile {
  modelVersion: '1.0.0',        // отдельно от версии движка
  engineVersion: string,
  input: BirthInput,
  instant: Instant,             // нормализованное время (TZ-1..6)
  pillars, pillarLabels, dayMaster, solarYear,
  elements:   { raw, effective, percent },   // каждое — Indicator
  yinYang, interactions, gua, meridians,
  indicators: { harmony, yinIndex, yangIndex, health },
  provenance: { verified: n, inferred: n, notVerified: n },
  warnings: Warning[]
}
```

Поле `provenance` — сводка по всему профилю. Оно даёт UI возможность честно показать «из 27 показателей 18 проверены, 6 предположены, 3 не рассчитываются», не пересчитывая ничего.

## 7. Загрузка JSON

Один код сборки, два источника чтения:

```
Node:     файлы data/*.json ──┐
                              ├──► assembleTables() ──► срезы ──► движок
Браузер:  bundle (инлайн)  ───┘
```

```js
// src/data/loader.js — общий, без ввода-вывода
export function assembleTables(rawMap, opts = { validate: true }) -> Tables
// src/data/node-loader.js   — читает диск
// src/data/browser-loader.js— читает бандл
```

**Почему в браузере бандл, а не `fetch`.** Требуется автономный HTML по `file://`, где `fetch` к соседним файлам блокируется политикой источника. Единый бандл снимает и это ограничение, и гонку 11 параллельных запросов, и расхождение версий таблиц. Цена — пересборка после правки данных; она включена в `npm run build`.

**Ключевой инвариант:** обе ветки обязаны собирать **идентичный** объект. В фазе 4 этот инвариант уже нарушался (бандл содержал сырые файлы без проекций, отчего браузер получал другой набор таблиц, чем тесты Node). Теперь он закреплён контрактным тестом (раздел 9.4).

## 8. Валидация и обработка ошибок

### 8.1 Три рубежа

| Рубеж | Когда | Инструмент | Реакция |
|---|---|---|---|
| Сборка | `npm run build` | `validate-json`, `validate-spec` | сборка не выпускается |
| Загрузка | старт приложения | `assembleTables({validate:true})` | баннер «данные повреждены», расчёт не запускается |
| Вызов | каждая функция | проверка входа | типизированная ошибка |

Проверка на старте дешёвая (структура, а не полная схема): версия пакета, наличие 11 таблиц, контрольные размеры коллекций (10 стволов, 12 ветвей, 24 сезона, 10 меридианов, 9 дворцов, 24 горы). Полная схема — обязанность сборки, повторять её в браузере незачем.

### 8.2 Классы ошибок

```js
AppError            code, message, details, userMessage
├── DataError       пакет данных повреждён или неполон
├── InputError      недопустимый ввод пользователя
├── RangeError_     дата вне поддерживаемого диапазона (K7)
├── NotVerified     запрошен неопубликованный алгоритм  ← не сбой
└── InternalError   нарушен инвариант — дефект программы
```

`NotVerifiedError` — намеренно отдельный класс: запрос к нереализуемому алгоритму не является поломкой, и UI обязан отличать «мы не знаем формулу» от «программа сломалась». Смешение этих случаев ведёт либо к панике на пустом месте, либо к сокрытию настоящих дефектов.

### 8.3 Политика

- **Расчётный слой бросает исключения.** Молчаливый `NaN`, распространяясь по графику, превращается в правдоподобную кривую — худший исход для этого проекта.
- **UI ловит на границе.** Один перехват вокруг пересчёта: ошибка показывается в строке состояния, предыдущий корректный результат остаётся на экране.
- **Частичный отказ допустим.** Падение расчёта звёзд не должно гасить столпы: каждая панель рисуется независимо, сбойная показывает своё сообщение.
- **Сообщения на русском, с причиной и действием**: «Дата вне диапазона 1700–2200 (конфликт K7). Введите год в этих пределах» — вместо «Invalid input».

## 9. Стратегия тестирования

Уровни: **STATIC → UNIT → CONTRACT → INTEGRATION → ARCHITECTURE → BROWSER → MUTATION**.

### 9.1 Unit
По файлу на модуль, только публичный интерфейс. Источник ожиданий — `tests/golden_cases.json` (74 случая: 47 GOLDEN из внешних публикаций, 23 INVARIANT, 4 REGRESSION). Значения не берутся из вывода нашего же кода, кроме структурных инвариантов.

### 9.2 Contract
Проверяют границы слоёв: срез содержит ровно объявленные таблицы; результат движка соответствует форме модели; `ChartSpec` не содержит доменных полей; сборка в Node и браузере совпадает.

### 9.3 Тест на чувствительность к данным — против ARCH-1
Ключевой тест этой фазы. Для каждой вынесенной в JSON константы: изменить значение → результат **обязан** измениться; вернуть → результат обязан совпасть с исходным.

```
для каждой константы K из {якоря, конверсии, длины циклов}:
    base = calc()
    K := K'          →  assert calc() != base   // иначе JSON декоративен
    K := исходное    →  assert calc() == base   // иначе есть побочный эффект
```

Именно этот тест обнаружил бы ARCH-1 автоматически. Он же не даст дефекту вернуться.

### 9.4 Architecture
Правила настоящего документа как исполняемые проверки (раздел 11).

### 9.5 Browser
DOM-заглушка, настоящего браузера в среде нет. **Это ограничение объявлено во всех отчётах**: заглушка проверяет разметку, события и отсутствие исключений, но не рендеринг, не шрифты и не реальные события мыши.

### 9.6 Mutation
`npm run test:mutation` вносит 26 намеренных дефектов и требует, чтобы валидатор их поймал (26/26 на текущий момент). Зелёный отчёт бесполезен, если детектор не умеет краснеть.

## 10. Браузер и автономный HTML

### 10.1 Веб-версия
Нативные ES-модули, без сборщика: `<script type="module" src="src/ui/app.js">`. Без транспиляции, без `node_modules`, отладка — по исходникам. Требуется HTTP (в комплекте `tools/serve.js`).

### 10.2 Автономный файл
`tools/build-standalone.js` обходит граф импортов в глубину, укладывает модули в топологическом порядке и оборачивает каждый в функцию с реестром экспортов; JSON инлайнится. Результат — один HTML (~179 КБ), работающий по `file://` без сервера и сети.

Ограничения, которые обязаны сохраняться: внешние зависимости запрещены (сборщик падает при первом же не-относительном импорте); замена строк выполняется только функциями-заменителями (иначе `$$` в данных будет искажён); порядок модулей детерминирован, поэтому сборка воспроизводима.

Проверяется `tools/standalone-test.js` — 21 проверка на собранном файле, а не на исходниках.

### 10.3 Визуальные требования
Компактная настольная раскладка, плотные элементы управления, серый технический фон, тонкая сетка, подписи и таблицы как в референсе. Никаких карточек, градиентов, стекла и декора. Палитра — только из `colors.json`.

## 13. Открытые вопросы и ограничения

1. **Формулы референса неизвестны** для индекса гармоничности, силы меридиана, итогового индекса здоровья, коэффициентов фаз Ци, агрегации Трёх обогревателей. Архитектура обязана их **не подделывать**: интерфейс возвращает `null`.
2. **7 из 9 конфликтов не разрешены** (K1–K5, K7, K8). Выбор по умолчанию задаётся данными и виден в результате, а не спрятан в коде.
3. **Скриншоты референса недоступны** — визуальное соответствие проверить нечем; раскладка воспроизводится по текстовым описаниям.
4. **Настоящего браузера в среде нет** — DOM-заглушка не заменяет проверку рендеринга.
5. **Гуа проверено лишь на 1900–2099**; в 2100 формула расходится с канонической таблицей.
6. **Диапазон дат противоречив** (K7: 1706–2198 против 1705–2200); движок принимает 1700–2200 и помечает края предупреждением.
