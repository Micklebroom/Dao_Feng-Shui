## 2. Классификация

Триаж начат с дефекта из отчёта, но поиск шёл по **классу причины**, а не по одному симптому: если пустой ряд ломает одну функцию, он способен ломать и соседние.

| ID | Дефект | Класс | Обоснование класса |
|---|---|---|---|
| BUG-01 | Необработанное исключение при пустом ряде | **HIGH** | Повышен со СРЕДНЕГО. Исключение покидает `recalc()`, интерфейс ложно сообщает «Расчёт выполнен», хотя расчёт провалился. Ложное подтверждение успеха опаснее видимой ошибки |

### Карточки

#### BUG-01 — HIGH
- **Симптом.** «Кол-во точек» ≤ 0 → `TypeError: Cannot read properties of undefined (reading 'meridians')`. Строка состояния показывает «Расчёт выполнен за 0.0 мс», график сохраняет старые линии, таблица не обновляется.
- **Корневая причина.** `src/ui/app.js:384`: `pts[Math.min(pts.length - 1, Math.floor(pts.length / 2))]`. При `length = 0` это `Math.min(-1, 0) = -1`, а `pts[-1] === undefined`. Исключение возникает в `renderAll()`, который вызывается **после** блока `try/catch` внутри `recalc()`, поэтому штатный перехват его не ловит.
- **Затронутый модуль.** `src/ui/app.js` → `renderMeridianTable()` (слой 5).
- **Исправление.** Явная проверка пустого ряда с честным сообщением вместо падения.
- **Риск регрессии.** Низкий: добавлена ветка для ранее падавшего состояния, поведение непустого ряда не тронуто.

#### BUG-02 — HIGH (латентный, найден при разборе BUG-01)
- **Симптом.** Наведение мыши на пустой график передаёт в `onHover` `points[-1] === undefined`; обработчик подсказки вызывает `s.accessor(pt)` и `pt.label` → исключение.
- **Корневая причина.** `src/chart/chart.js:169`: тот же приём `Math.min(points.length - 1, idx)` без проверки пустоты.
- **Затронутый модуль.** `src/chart/chart.js` (слой 4).
- **Исправление.** При пустом ряде наводиться не на что: скрываем линию наведения и сообщаем `onHover(null)` — тем же способом, что и при уходе мыши.
- **Риск регрессии.** Низкий: путь непустого ряда не изменён (проверено контрольным прогоном).

#### BUG-03 — HIGH (первопричина)
- **Симптом.** `count = 0/−10` давал пустой ряд; `count = 5000` считался 213 мс; `from = 99999` строил ряд с меткой «99999»; `scale = 'week'` молча давал пустой результат.
- **Корневая причина.** `buildTimeSeries()` вызывал `validateInput()` только для даты рождения. Параметры ряда шли в движок без проверки — расхождение в политике: одна и та же величина (год) отвергалась для рождения и принималась для ряда.
- **Затронутый модуль.** `src/model/profile.js` (слой 3).
- **Исправление.** Добавлена `validateSeriesOptions()`: `count` в 1…`MAX_SERIES_POINTS`, `from` в объявленном диапазоне дат, `scale` из списка допустимых.
- **Риск регрессии.** Средний — новая валидация могла отвергнуть корректные сценарии. Снят: все пять масштабов и граничное значение `count = 1200` проверены тестами.

#### BUG-04 — LOW
- **Симптом.** `<input type="number" id="s-count">` без `min`/`max` позволял вводить любое значение.
- **Корневая причина.** Ограничения не были объявлены в разметке.
- **Затронутый модуль.** `index.html` (слой 5).
- **Исправление.** `min="1" max="1200"` и `min="1700" max="2200"` + всплывающие подсказки.
- **Риск регрессии.** Отсутствует: браузерная подсказка дополняет, а не заменяет проверку в модели.
