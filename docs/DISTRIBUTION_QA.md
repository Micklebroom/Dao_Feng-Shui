(проверка «контрольная сумма … совпадает»). При пересборке из того же дерева

контрольную сумму ZIP — выписанное здесь значение устаревало бы в момент
записи. Это не дефект, а следствие самоссылочности; актуальные значения
всегда в `distribution/manifest.json`, и они проверяются автоматически.
Суммы трёх остальных файлов от содержимого документа не зависят.

## 3. Найденные и устранённые дефекты

Все пять найдены самими проверками этой фазы, а не наблюдением «работает».

### DIST-01 (HIGH) — служебные файлы QA попадали в поставку и ломали воспроизводимость
`tools/.qa-results.json` и `tools/.dist-results.json` копировались в архив.
Они переписываются при каждом прогоне тестов, поэтому ZIP и его контрольная
сумма менялись от сборки к сборке — контрольные суммы в манифесте теряли смысл.
**Причина:** каталог `tools/` копировался целиком, без фильтра.
**Исправление:** `build-distribution.js` вычищает из стейджинга скрытые файлы
и `*.log`; оба файла внесены в `.gitignore`.
**Проверка:** «повторная сборка даёт тот же FENG_SHUI_MVP.zip» — теперь проходит.

### DIST-02 (MEDIUM) — тест автономного файла падал у получателя пакета
`tools/standalone-test.js` искал `dist/feng_shui_mvp.html`. В распакованной
поставке этого пути нет (файл лежит как `app/index.html`), поэтому команда из
README завершалась `ENOENT`.
**Исправление:** поиск по списку кандидатов `dist/`, `distribution/`, `app/index.html`
с понятным сообщением, если не найден ни один.
**Проверка:** из распакованного архива — 21 проверка, 0 провалов.

### DIST-03 (MEDIUM) — проверка поставки падала внутри самой поставки
`tools/distribution-test.js` требовал каталог `distribution/`, которого внутри
архива нет.
**Исправление:** корректная деградация — сообщение и выход с кодом 0.

### DIST-04 (LOW) — ссылка на несуществующий файл в документации
Проверка путей, упомянутых в `README.md`, выявила ссылки на `data/weights.json`.
Файл был поглощён `indicators.json` ещё в фазе 4, но упоминания остались
в `README.md`, `index.html` (окно «О программе»), `docs/ALGORITHMS.md`,
`src/engine/elements.js` и `src/engine/meridians.js` — пользователь поставки
искал бы отсутствующий файл. Заменено на `data/indicators.json`.
Дефект документации, на расчёты не влияет; в README также исправлено
устаревшее имя `dist/fengshui-standalone.html`.

### DIST-05 (LOW) — ложное срабатывание проверки на localhost
Проверка «нет обращений к localhost» ловила слово `localhost` в тексте
комментария исходника, а не URL.
**Исправление:** регулярное выражение сузили до реальных обращений
(`http(s)://host`, `//host`, `host:порт`). Настоящих обращений к localhost
в поставке нет.

## 4. Backend не обязателен

Требование «для client-side confirmed calculations backend не должен быть
обязательным» выполнено и проверено:

* автономный HTML не содержит **ни одной** внешней ссылки (`src`/`href`);
* нет `<script src>` и `<link rel=stylesheet>` — код, стили и все 12 таблиц
  данных встроены в файл;
* инлайн-скрипт исполнен вне какого-либо сервера: расчёт, графики и выгрузка
  JSON отработали;
* в манифесте зафиксировано `runtime.backendRequired: false`,
  `networkRequired: false`;
* внешних зависимостей — 0.

Два режима работы различаются меткой `<meta name="fs-build">`, которую
проставляет сборщик; приложение показывает текущий режим в панели «Загрузка».

| Кнопка | Автономно (`file://`) | С сервера |
|---|---|---|
| Скачать JSON | Собирается на клиенте | Собирается на клиенте |
| Скачать программу | Копия текущей страницы | Готовый файл поставки |
| Скачать полный пакет | **Недоступно**, выдаётся честное сообщение | Готовый архив |

ZIP невозможно собрать в браузере без внешних библиотек. Подделывать архив
(отдавать переименованный текст) недопустимо, поэтому в автономном режиме
приложение прямо сообщает, где взять файл. Проверка «без сервера ZIP не
подделывается» это фиксирует.

## 5. Детерминированность

Сборка дважды подряд даёт **побайтово одинаковые** файлы (проверяется
автоматически, 5 проверок). Обеспечено:

* фиксированное время файлов в архиве (`touch -t`), `zip -X`;
* отсутствие `Date.now()` и случайных значений в содержимом;
* порядок таблиц задаётся списком `DATA_FILES`, а не обходом ключей.

Дата сборки намеренно **не** записывается в артефакты: иначе контрольные
суммы менялись бы при каждом запуске. Версия берётся из `package.json`.

## 6. Единый источник JSON

`feng_shui_data.json` в поставке и файл, который отдаёт кнопка «Скачать JSON»,
собираются **одним и тем же кодом** — `src/data/package.js`. Совпадение
проверяется дважды: сборкой в Node и перехватом реальной выгрузки из
работающего приложения (обе — байт-в-байт).

Это защита от класса дефектов «в поставке одно, в выгрузке другое».
Мутационная проверка: искусственная порча файла поставки была поймана
**шестью** независимыми проверками — стенд действительно способен падать.

## 9. Что НЕ проверено (ограничения)

Раздел обязателен: скрывать неопределённость нельзя.

1. **Настоящего браузера в среде нет.** Все проверки интерфейса выполнены на
   DOM-заглушке (`tools/browser-test.js`). Проверено: исполнение кода,
   состояние DOM, обработчики, консоль. **Не проверено:** пиксельный
   рендеринг, шрифты, реальная геометрия SVG, поведение диалога `<dialog>`,
   различия движков браузеров.
2. **Реальное сохранение файла на диск не проверялось.** Перехватывается
   вызов `a.click()` на ссылке с атрибутом `download` и содержимое `Blob`.
   Поведение диалога загрузки, политики браузера в отношении `file://`
   и `Content-Disposition` остаются непроверенными.
3. **Запасной путь «Скачать программу» в автономном режиме проверен частично.**
   Он опирается на `outerHTML`, которого в DOM-заглушке нет; проверено только
   то, что приложение не падает и честно сообщает результат. Основной путь
   (готовый файл с сервера) проверен полностью, на реальном HTTP.
4. **Совместимость с браузерами заявлена, но не измерена.** Использованы
   `Blob`, `URL.createObjectURL`, `<a download>`, `fetch`, ES-модули,
   `<dialog>`. Всё это поддерживается современными браузерами, но
   фактических прогонов в Chrome/Firefox/Safari/Edge не было.
5. **Референсные изображения недоступны** (подтверждено трижды: HTTP 500).
   Визуальное соответствие эталону не может быть подтверждено; утверждений
   о пиксельной точности не делается.
6. **Статусы алгоритмов не менялись.** Весовая модель силы стихий и
   меридианов остаётся **INFERRED**; показатели с невосстановленным
   алгоритмом по-прежнему возвращают `null`. Открытые вопросы MEDIUM/LOW
   из фаз 10–11 (RT-05, RT-06, RT-08, RT-09, ARCH-2…ARCH-6) не закрывались:
   упаковка их не затрагивает.

## 10. Заключение

самодостаточен: из него запускаются и приложение, и весь контроль качества.

**Статус остаётся прежним: MVP / экспериментальное расчётное приложение.
НЕ production-ready.** Основание — не дефекты упаковки (их нет), а статус
самих алгоритмов: ключевая весовая модель имеет статус INFERRED, а
референсная спецификация (`FenShui_4.chm`) остаётся недоступной.

Публикация (`git push`) в этой фазе **не выполнялась** — согласно указанию
«не публикуй до завершения проверки». Проверка завершена; решение о
