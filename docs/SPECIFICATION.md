| Правило | Значение |
|---|---|
| Идентификаторы | стабильные латинские ID; русские названия — только подписи; китайские термины в полях `han`/`pinyin` |

## 1. ГЛОБАЛЬНЫЕ ПРАВИЛА

### 1.1 Календарные правила (CAL) — VERIFIED

| ID | Правило |
|---|---|
| CAL-1 | Пролептический григорианский календарь на всём диапазоне |
| CAL-2 | Солнечный год начинается в момент **Ли Чунь** (立春, λ☉ = 315°) — не в лунный НГ и не 1 января |
| CAL-3 | Солнечный месяц начинается в момент **сектантского термина 節**; средние термины 氣 границ не задают |
| CAL-4 | Месяц, начинающийся на Ли Чунь, имеет ветвь 寅 (индекс 2), `ordinal = 0` |
| CAL-5 | Месяцы 子 (ordinal 10) и 丑 (ordinal 11) в декабре–начале февраля принадлежат **предыдущему** солнечному году |

### 1.2 Правила часовых поясов (TZ) — VERIFIED

> **Устраняет дефект AUDIT A-08:** ранее столпы года/месяца брались из UTC-момента,
> а дня/часа — из локальных чисел. Две шкалы в одной модели.

| ID | Правило |
|---|---|
| TZ-1 | Вход всегда трактуется как **местное гражданское время места события** |
| TZ-2 | `instantJD = julianDay(local) − tzOffsetHours/24` [+ поправка истинного солнечного времени] |
| TZ-3 | **Все четыре столпа** определяются из **одного** `instantJD`. Смешение шкал запрещено |
| TZ-4 | Локальная дата для столпа дня восстанавливается обратно: `localJD = instantJD + tzOffsetHours/24` |
| TZ-5 | Историческая база часовых поясов и летнего времени **не реализуется** в MVP → заглушка `PH-TZDB` |
| TZ-6 | Поправка истинного солнечного времени (опция): `Δмин = (longitude − tzOffsetHours·15)·4`. Уравнение времени не применяется → `PH-EOT` |

### 1.3 Граничные правила (BND)

| ID | Правило | Статус |
|---|---|---|
| BND-1 | Границы терминов полуоткрыты: момент принадлежит **новому** периоду (`instantJD >= termJD`) | VERIFIED |
| BND-2 | Границы 24 гор полуоткрыты `[start, end)`; гора N2 пересекает 0° | VERIFIED |
| BND-3 | Поздний час Цзы (23:00–23:59) → **следующий** день (晚子), переключаемо | PARTIALLY VERIFIED · K4 |
| BND-4 | Точность моментов терминов **±15 мин**; у полуночи дата может сместиться на сутки | PARTIALLY VERIFIED |
| BND-5 | **Диапазон применимости движка: 1900–2099.** Вне его формула Гуа некорректна (A-04) | VERIFIED |

## 2. АСТРОНОМИЧЕСКИЙ СЛОЙ

### A1. julianDay — VERIFIED

```
INPUT         CivilDateTime (трактуется как UTC)
NORMALIZATION если month ≤ 2: year −= 1, month += 12
LOOKUP        —
RULES         A = ⌊year/100⌋;  B = 2 − A + ⌊A/4⌋
CALCULATION   JD = ⌊365.25(Y+4716)⌋ + ⌊30.6001(M+1)⌋ + D + dayFrac + B − 1524.5
OUTPUT        number (JD)
DEPENDENCIES  —
VALIDATION    примеры Meeus 7.a/7.b; обратимость на 1900–2100
SOURCE        Meeus, Astronomical Algorithms 2nd ed., ch.7
```
Тесты: `GT-A1-01…04`

### A2. apparentSolarLongitude — VERIFIED

```
INPUT         { jdTT }
NORMALIZATION T = (jdTT − 2451545.0)/36525
RULES         L0 = 280.46646 + 36000.76983·T + 0.0003032·T²
              M  = 357.52911 + 35999.05029·T − 0.0001537·T²
              C  = (1.914602 − 0.004817T − 0.000014T²)·sin M
                 + (0.019993 − 0.000101T)·sin 2M + 0.000289·sin 3M
              Ω  = 125.04 − 1934.136·T
CALCULATION   λ = (L0 + C − 0.00569 − 0.00478·sin Ω) mod 360
OUTPUT        number ∈ [0, 360)
VALIDATION    Meeus 25.a → 199.90895°, допуск 0.001°
SOURCE        Meeus ch.25
```

> **Обоснование тригонометрии.** `sin`/`cos` применяются **исключительно**
> потому, что видимое движение Солнца по эклиптике физически описывается
> тригонометрическим рядом с опубликованными коэффициентами. Это **не**
> имитация формы какого-либо графика фэн-шуй. Единственное место в проекте.

Тесты: `GT-A2-01…02`

### A3. solarTermInstant — PARTIALLY VERIFIED

```
INPUT         { year, longitude ∈ {0,15,…,345} }
NORMALIZATION approxDoy = ((longitude − 280) mod 360)/0.9856 + 1
              jdGuess   = JD(year,1,1) + approxDoy + ΔT/86400
RULES         детерминированный Ньютон, численная производная (h = 0.02 сут),

CALCULATION   solve λ(jdTT) = target;  jdUTC = jdTT − ΔT(year)/86400
OUTPUT        number (JD в шкале UTC)
DEPENDENCIES  A1, A2, A6
VALIDATION    4 точки 2025 г. против астрономических таблиц (допуск 20 мин);
              Ли Чунь ∈ [3, 5] февраля для 1900–2100
```

сдвинет столп месяца. Объявлено, не скрыто.

Тесты: `GT-A3-01…05`

## 5. ЧИСЛО ГУА

### H12. mingGua — VERIFIED **только для 1900–2099**
```
INPUT   { solarYear ∈ [1900, 2099], gender }
NORM    год солнечный (CAL-2); K8: меньшинство школ берёт лунный НГ
RULES   s = цифровой корень всех четырёх цифр года → 1..9
        муж: gua = 11 − s → 1..9; если 5 → 2
        жен: gua = s + 4  → 1..9; если 5 → 8
```
> **AUDIT A-04.** Численно доказана эквивалентность каноническому правилу веков
> на **402 парах (год × пол), 0 расхождений**. Алгебраически:
> digitRoot(19xx) = digitRoot(last2) + 1 (mod 9) ⇒ `11 − (s+1) = 10 − s`;
> digitRoot(20xx) = digitRoot(last2) + 2 (mod 9) ⇒ `11 − (s+2) = 9 − s`.
> **Граница найдена:** вне 1900–2099 эквивалентность нарушается (2100: наша 8,
> канон 9) → для 2100+ статус `NOT_VERIFIED`.

Тесты: `GT-H12-01…05`

не ошибка: это **разные системы**, смешивать нельзя (K6 RESOLVED).

> **AUDIT A-01. Отозванный источник: Су Джок.** Ранее фигурировал как
> легитимирующий модель. Проверка: **современная система Пак Чжэ Ву,

> не китайский канон и не метод расчёта по календарю. Легитимной опорой
> остаётся только классическое Цзан-Фу ↔ 5 стихий.
