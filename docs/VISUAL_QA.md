## 0. Оговорка о достоверности — читать до выводов

**Оригинальные скриншоты референсной программы в сессию не передавались.** Ни одно утверждение здесь не является заявлением о попиксельном соответствии, и такое соответствие **не проверялось и не может быть проверено** имеющимися средствами.

Попытка получить изображения предпринята повторно в этой фазе:

```
http://feng-shui.net.ru/progV4_2.files/image001.gif → HTTP 500
http://feng-shui.net.ru/progV4_1.files/image001.jpg → HTTP 500
```

Это третье независимое подтверждение (фазы 1, 2, 9), что изображения референса недоступны. Все 18 графиков `progV4_2.files/image001–018.gif` и скриншоты главного окна остаются **NOT VISUALLY VERIFIED**.

**Что служило основанием аудита:**
1. Текстовые описания автора с `feng-shui.net.ru` (progV4_1.htm, progV4_2.htm, progr.htm) — извлечены в фазе 1;
2. Визуальная спецификация, заданная пользователем: compact desktop, серая техническая рабочая область, плотные элементы управления, таблицы, тонкая сетка, цветные серии, легенды, оси, подсказки, технический вид; прямой запрет на SaaS-дашборд;
3. Прямые измерения интерфейса (CSS, разметка, отрисованный DOM) — не оценки на глаз.

**Дополнительное ограничение:** настоящего браузера в среде нет. Измерялись CSS-значения и состояние DOM, но **не** итоговый растр, сглаживание шрифтов и реальная типографика.

## 3. Найденные визуальные дефекты

### VIS-01 — расхождение цвета «Металл» между CSS и данными · **HIGH**

**Симптом.** Один и тот же элемент окрашен по-разному в разных частях интерфейса:

```
линия «Металл» на графике и в легенде : #78909c   (из colors.json)
подпись «Металл» в таблице (.el-metal): #5b6b75   (из styles.css)
```

**Корневая причина.** `src/ui/styles.css` содержал собственную копию палитры стихий. В фазе 4 палитра была централизована в `data/colors.json`, но CSS-копия осталась и со временем разошлась. Это нарушает правило «единственный источник цвета», введённое в фазе 4.

**Почему HIGH.** Цвет — единственный способ сопоставить линию графика с её строкой в таблице. Разные оттенки одного понятия ломают это сопоставление; проверка данных при этом молчит, поскольку CSS ей не подконтролен.

**Затронуто:** `src/ui/styles.css` (слой 5). Расчёт не затронут.

### VIS-02 — ось Y без названия и единиц · **MEDIUM**

**Симптом.** На оси Y только числа. Пользователь не может определить, что означает «15.9»: проценты, условные единицы или что-то иное. При переключении режимов (меридианы → стихии → индексы → Инь/Ян) смысл шкалы меняется, а подпись — нет.

**Корневая причина.** `renderLineChart` поддерживает параметр `yLabel`, но `src/ui/app.js` его никогда не передавал.

**Почему MEDIUM.** Требование «axes» из визуальной спецификации выполнено частично: деления есть, идентификация величины отсутствует. Для приложения, где часть величин имеет статус INFERRED, безымянная шкала особенно нежелательна.

**Затронуто:** `src/ui/app.js`, `src/chart/chart.js` (слои 4–5).

### VIS-03 — единый шрифтовый стек без запасного варианта для CJK · **LOW**

Иероглифы объявлены как `"Noto Sans CJK SC", "Microsoft YaHei", SimSun, serif`. Если ни один не установлен, откат на `serif` даст неровную высоту строки. Проверить нечем: настоящего браузера нет, растр недоступен. **Не исправляю** — согласно заданию правятся только HIGH и MEDIUM, а без возможности увидеть результат правка была бы гаданием.

## 5. Выполненные исправления

Согласно заданию исправлены только HIGH и MEDIUM. Расчётный движок не изменялся: `git diff` по `src/engine/`, `src/model/`, `data/`, `algorithms/` — **пусто**.

### VIS-01 (HIGH) — устранено дублирование палитры

**Изменение.** Правила `.el-*` теперь генерируются из `data/colors.json` при запуске (`injectElementColors()` в `src/ui/app.js`); в `styles.css` осталось только резервное объявление на случай, если скрипт не отработал, приведённое в соответствие с данными.

```js
const pal = T.colors.palettes.elements.byId;
const rules = Object.entries(pal).map(([id, hex]) => `.el-${id}{color:${hex}}`).join('\n');
```

**Проверка.** Расхождений с данными: **0** (было 1).

**Побочный дефект, найденный при внесении правки.** Первая версия использовала `document.head` и уронила запуск приложения на тестовой DOM-заглушке, где `head` отсутствует. Исправлено выбором точки вставки `head → body → documentElement` с проверкой: оформление не имеет права ронять приложение.

### VIS-02 (MEDIUM) — ось Y получила название и единицы

**Изменение.** Реализован параметр `yLabel` в `renderLineChart` (был объявлен в комментарии, но не поддержан). Подпись рисуется вертикально вдоль шкалы; левое поле увеличивается с 38 до 50 px только при наличии подписи, чтобы текст не наезжал на числа.

Подпись зависит от режима и **несёт статус достоверности**, чтобы шкала INFERRED-величин не выглядела измеренной:

| Режим | Подпись оси Y |
|---|---|
| Меридианы | Сила меридиана, усл. ед. (INFERRED) |
| Стихии | Доля стихии, % (INFERRED) |
| Индексы | Индекс, 0–100 (INFERRED) |
| Инь/Ян | Инь / Ян, усл. ед. и % (INFERRED) |

### VIS-03 (LOW) — намеренно не исправлялось
