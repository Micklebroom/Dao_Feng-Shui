## 2. НАЙДЕННЫЙ ДЕФЕКТ

### BUG-01 — необработанное исключение при пустом временном ряде

| Поле | Значение |
|---|---|
| **TEST ID** | QA-13-4 |
| **INPUT** | Поле «кол-во» на панели графика = `-10` (также воспроизводится при `0`) |
| **EXPECTED** | Приложение остаётся работоспособным: либо понятное сообщение, либо безопасное приведение значения. Исключение не покидает обработчик |
| **ACTUAL** | `TypeError: Cannot read properties of undefined (reading 'meridians')` — **необработанное**, всплывает за пределы `recalc()` |
| **PASS/FAIL** | **FAIL** |
| **ERROR** | `at renderMeridianTable (src/ui/app.js:389)` → `renderAll (app.js:85)` → `recalc (app.js:67)` |

**Корневая причина (доказана, не предположена):**

```js
// src/ui/app.js:384
const cur = pts[Math.min(pts.length - 1, Math.floor(pts.length / 2))];
```

При пустом ряде `pts.length = 0`:

```
Math.min(0 - 1, Math.floor(0 / 2)) = Math.min(-1, 0) = -1
pts[-1] === undefined
undefined.meridians → TypeError
```

Движок отрабатывает корректно: `buildTimeSeries(..., {count: -10})` возвращает `points: []` без исключения. Дефект целиком в слое UI.

**Почему это существенно.** Исключение возникает в `renderAll()`, который вызывается **после** блока `try/catch` внутри `recalc()`, поэтому штатный перехват ошибок его не ловит. Пользователь видит несогласованное состояние: строка состояния сообщает «Расчёт выполнен за 0.0 мс», график сохраняет 10 старых линий, а таблица меридианов не обновляется. То есть **интерфейс утверждает, что расчёт успешен, хотя он провалился**.

**Достижимость пользователем:** да. Поле объявлено как `<input type="number" id="s-count" value="30">` — **без атрибутов `min`/`max`**, поэтому ввод `0` или отрицательного значения ничем не ограничен.

**Оценка тяжести: СРЕДНЯЯ.** Данные не портятся и неверные результаты не показываются, но нарушается правило обработки ошибок из ARCHITECTURE §8.3 («UI ловит на границе») и пользователь получает ложное подтверждение успеха.

**Не исправлено намеренно** — согласно заданию фазы: «НЕ ИСПРАВЛЯЙ КОД. Сначала диагностика.»

## 4. Три дефекта нашлись в самом тестовом стенде

Первый прогон дал 6 FAIL. Проверка каждого показала, что **три из них — ошибки моих проверок, а не приложения**. Фиксирую честно, поскольку иначе отчёт обвинял бы исправный код.

| Моя проверка | Что я сделал не так | Как убедился |
|---|---|---|
| QA-05-1 (timezone) | Сравнивал пояса UTC+0 и UTC+12 на дате **вдали от границы сезона**. Столпы дня и часа при одинаковом локальном времени совпадать и обязаны | Прямой вызов движка: на 04.02.2025 (рядом с Ли Чунь) UTC+14 даёт солнечный год 2024, UTC+0 — 2025. Пояс учитывается |
| QA-11-2/3 (tooltip) | Отправлял `mousemove` в корень `<svg>`, тогда как слушатели висят на прозрачном overlay-прямоугольнике (`src/chart/chart.js:165`) | Отправка в overlay: `display=block`, 209 символов текста, `mouseleave` → `none` |
| QA-17-1 (year) | Искал год регуляркой по `textContent`, а DOM-заглушка переставляет вложенные теги | Чтение из `innerHTML`: 2024 → 2025 |

Кроме того, критерий QA-CON-1 был изначально неверен: он требовал ноль `console.error` при том, что часть проверок **намеренно** подаёт неверный ввод и обязана вызывать ошибки. Критерий переформулирован на «ноль непредвиденных ошибок» с отдельным подсчётом ожидаемых.

После исправления стенда: **69/70**.

## 5. Ограничения этого прогона

Перечисляю прямо, чтобы результат не выглядел надёжнее, чем он есть.

1. **Настоящего браузера в среде нет.** Проверки идут на DOM-заглушке (`tools/browser-test.js`). Проверено: выполнение кода, состояние DOM, обработчики событий, консоль. **Не проверено:** пиксельный рендеринг, шрифты, реальная геометрия SVG, прокрутка, поведение при изменении размера окна, отличия движков браузеров.
2. **Наведение мыши эмулируется** синтетическим объектом события с координатами; настоящий hit-testing не выполняется.
3. **«Перезагрузка страницы»** эмулируется повторным импортом модуля с новым DOM. Это не проверяет кэширование, работу кнопки «Назад» и состояние `file://`.
4. **Визуальное соответствие референсу не проверялось** — скриншоты оригинальной программы недоступны (зафиксировано в фазах 1–2).
5. Значения показателей на корректность **не проверялись** — это задача golden-тестов; здесь оценивалось только поведение интерфейса.

## 6. Вывод

Интерфейс устойчив: 20 из 20 областей работают, включая все пять масштабов времени, четыре режима графика, границы диапазона дат, переходы Ли Чунь и Цзинчжэ, повторные пересчёты и перезагрузку. Валидация ввода отрабатывает корректно во всех восьми проверенных сценариях неверных данных и выдаёт понятные русские сообщения вместо `NaN`.

Найден **один дефект (BUG-01)**: при `кол-во точек ≤ 0` необработанное исключение покидает `recalc()`, и интерфейс ложно сообщает об успешном расчёте. Достижим пользователем, так как у поля нет ограничения `min`.

**Код не исправлялся.** Устранение BUG-01 — предмет следующей фазы, по протоколу BUG → ROOT CAUSE → CODE CHANGE → RUN → TEST → REGRESSION TEST.
